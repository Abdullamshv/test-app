## Решения

**Статусы и фильтр.** Фильтр не реализован, поэтому это план, а не готовое решение. «Завершённые» = `finished`. «Предстоящие» = `scheduled`, `live` и `postponed`, при этом `live` идёт первым: матч, который идёт или перенесён, ещё не закончен, и иначе он пропал бы из обоих фильтров. «Все» = всё, включая неизвестные статусы.

**Неочевидные случаи в данных, которые обработаны в коде:**

- `startsAt: null` (перенесённый матч m7): показываю «Дата уточняется». `new Date(null)` дал бы 1 января 1970. Некорректная строка даты (Invalid Date) обрабатывается так же.
- `score: null`: вместо счёта показываю «—», обращения к `score.home` нет.
- Счёт 0:0 (m2): проверка идёт по `null`, а не по истинности, поэтому нули видны.
- `minute` есть только у `live`: статус выглядит как «Идёт · 67'».
- Неизвестный статус: показывается исходная строка, приложение не падает. Тип статуса допускает любую строку.
- Длинные названия («Пари Нижний Новгород»): `numberOfLines={2}`, вёрстка не ломается.
- Три матча из Москвы: ключи списка и избранное строятся по `id` матча, а не по городу или названию.
- Ответ сервера — объект `{ round, matches }`, а не массив. Проверяю, что `matches` — массив, иначе показываю ошибку.
- `fetch` не бросает ошибку на 404 и 500, поэтому статус ответа проверяется вручную (`response.ok`).
- `MATCHES_URL` в шаблоне содержал заглушку `OWNER/REPO` и вернул бы 404. Заменил на адрес файла в этом репозитории.
- README пишет «Node 20+», но Expo SDK 57 требует Node 22.13 или новее.

1. Некорректная работа звёзд в избранном

Проверка избранного работала некорректно из-за использования Boolean(favorites.indexOf(id)). indexOf возвращает индекс элемента, а не true или false. Из-за этого отсутствующий элемент (-1) воспринимался как избранный, а первый элемент массива (0) — наоборот. В итоге звёзды отображались неправильно.

Вторая проблема была в обновлении состояния, массив favorites изменялся напрямую через push и splice. Поскольку ссылка на массив оставалась прежней, React не распозновал изменение и не обновлял интерфейс сразу.

Что я сделал:

Я заменил проверку на favorites.includes(id), чтобы корректно определять, находится ли элемент в избранном. Сделал обновление массива иммутабельным. Теперь используется setFavorites с filter для удаления и созданием нового массива при добавлении.

2. Индикатор «Обновлено N сек. назад»

Из-за неверной настройки useEffect, счетчик зависал на секудну. Интервал создавался один раз и использовал значение seconds из первого рендера. Поэтому каждую секунду состояние устанавливалось в 1, вместо того чтобы увеличиваться дальше.

При этом since вообще не учитывался, поэтому счётчик не был привязан к реальному времени обновления данных. Ещё не было очистки интервала при размонтировании компонента.

Что было сделано:

Переделал логику счётчика, теперь в состоянии хранится текущее время now, а количество секунд рассчитывается как разница между now и since. 

При изменении since эффект перезапускает интервал, поэтому отсчёт корректно начинается заново. Дополнительно добавил очистку через clearInterval в cleanup-функции, чтобы интервал не продолжал работать после размонтирования компонента.

## Как я использовал ИИ

Работал с Kiro, ИИ-агентом в IDE: он читал проект, писал код и запускал `npx tsc --noEmit` и сборку веб-бандла. Баги из части 2 разбирали вместе: он объяснял причину, я пересказывал её своими словами.

Где ответ ИИ был неверным или неполным:

1. В первом черновике этого файла стояло, что `extraData` добавлен в `FlatList`, хотя `FlatList` на экране тогда ещё не было. Расхождение нашлось при сверке текста с кодом. Фразу убрали, `extraData` появился в коде позже.
2. Первый запуск `npm install` упал с ошибками `EPERM` и `ENOTEMPTY` и изменил `package-lock.json`. Это стало видно по `git status`: файл вернули к закоммиченной версии, зависимости поставили через `npm ci`.
3. Формат даты через `toLocaleString('ru-RU')` предложен без подтверждения в документации Expo для Hermes. На телефоне он пока не проверен.

Как проверял результат: `npx tsc --noEmit`, сборка `expo export --platform web`, запуск `npm run web` в браузере. Вручную проверил, что звёздочки и «Обновить» работают.
